# IdeaTree 仕様書

## 1. プロジェクト概要
- **対象OS**: macOS
- **開発言語**: TypeScript (Frontend / React+Vite想定) + Rust (Backend / Tauri想定)
- **コンセプト**: トニー・ブザンが提唱するマインドマップの法則に忠実な、UIと操作性に優れた思考整理ツール。

## 2. コア機能要件（トニー・ブザンの法則に準拠）
1. **セントラルイメージ**: 中央から開始し、中心には画像または象徴的なビジュアルを配置できる。
2. **ブランチ（枝）**: 直線ではなく、有機的な曲線で描画されること。中心に近いほど太く、外側にいくほど細くなる。
3. **1ブランチ＝1ワード**: 枝の上に乗せる言葉は単語（キーワード）を基本とする。
4. **カラー**: メインブランチごとに異なる色を割り当て、カラフルな構成にする。
5. **強調と連想**: 自由なフォント選択、文字の大小、アイコンや画像の追加による視覚的強調を可能にする。
6. **保存・エクスポート形式**:
   - **JSON**: プロジェクトデータの保存と読み込み（再編集用）。
   - **SVG**: マインドマップのベクター画像エクスポート（曲線やカラフルな描画を劣化なく保存）。

## 3. 操作性（キーボードファースト）
マウスを使わずに思考のスピードを止めない操作性を実現する。マウスでも、ノードのクリック（選択）とダブルクリック（編集）ができる。

| キー | 動作 |
| --- | --- |
| `Tab` | 選択ノードの子ノードを追加し、テキスト入力を始める（折りたたまれていれば自動で展開） |
| `Enter` | 選択ノードの兄弟ノードを追加し、テキスト入力を始める（中心ノードでは何もしない） |
| `F2` / ダブルクリック | 選択ノードのテキストを編集する |
| `→` / `←` | 最初の子ノード / 親ノードへ移動する（折りたたまれたノードでは子へ進まない） |
| `↓` / `↑` | 次の兄弟 / 前の兄弟へ移動する |
| `Delete` / `Backspace` | 選択ノードをサブツリーごと削除する（中心ノードは削除できない） |
| `Option + ↑` / `Option + ↓` | 兄弟の順序を入れ替える（1つ前 / 1つ後ろへ） |
| `Option + →` | 前の兄弟の最後の子にする（インデント。前の兄弟が折りたたまれていれば自動で展開） |
| `Option + ←` | 親の直後の兄弟にする（アウトデント。中心ノードの子になると、新しいメインブランチとして色が割り当てられる） |
| `Space` | 選択ノードの子孫を折りたたむ / 展開する |
| `Cmd + C` / `Cmd + V` / `Cmd + X` | サブツリーのコピー / 選択ノードの子としてペースト / カット（システムのクリップボード経由。後述） |
| `Cmd + Z` / `Cmd + Shift + Z` | 元に戻す / やり直す（最大 100 件） |
| `Cmd + B` / `Cmd + I` | 選択ノードの太字 / 斜体を切り替える |
| `Cmd + K` | スタイルパネルを開閉する（色・フォント・文字サイズ） |
| `Cmd + S` | JSON で保存する（保存先が決まっていれば上書き） |
| `Cmd + Shift + S` | 保存先を決めて JSON で保存する |
| `Cmd + O` | JSON ファイルを開く |
| `Cmd + Shift + E` | SVG 画像として書き出す |

### ノードの移動
- **マウスのドラッグ**: ノードを押して、4px を超えて動かすと、ドラッグが始まる（それ以下は、クリック）。別のノードの上で離すと、そのノードの子（末尾）につなぎ替える。ドラッグ中は、離すとつなぎ替えられるノードが強調表示される。何もない場所や、つなぎ替えられないノードの上（自分自身・子孫・今の親・中心ノードのドラッグ）で離すと、何も起きない。`Escape` でドラッグを取り消せる。左ボタンのみ。兄弟の順序の指定は、キーボード（`Option + ↑ / ↓`）で行う。
- 移動は、ノードを子孫ごと、木構造の中で移動する操作（自由な座標への移動はない。位置は、自動のレイアウトが決める）。
- 動かせないとき（先頭・末尾、前の兄弟がない、メインブランチのアウトデント、中心ノード）は、何もせず、履歴にも残さない。移動は 1 手の履歴になり、選択は移動したノードのまま。

### システムのクリップボードとの連携
- `Cmd + C` / `Cmd + X` は、サブツリー（折りたたみ・スタイルを含む）を、アプリの中と、システムのクリップボード（JSON のテキスト）の両方に保持する。システムのクリップボードに書けなくても、アプリの中のコピーは使える。
- `Cmd + V` は、システムのクリップボードを読み込んで、次のように貼り付ける。
  - **IdeaTree のサブツリー**（別のウィンドウでコピーしたものを含む）: 選択ノードの子として貼り付ける。貼り付けたノードを選択する。
  - **普通のテキスト**: 空行を除き、1 行 1 ノードで、選択ノードの子として追加する（最大 200 行）。最初に追加したノードを選択する。
  - **貼り付けられない内容**（空のテキスト、IdeaTree のサブツリー以外の JSON のように見えるテキスト、200 行を超えるテキスト）: 何もしない。
  - 読み込めたときは、システムのクリップボードを優先する。読み込み自体に失敗したときだけ、アプリの中のコピーを貼り付ける。
- 折りたたまれたノードに貼り付けると、自動で展開する。貼り付けは、1 手の履歴になる。

### テキスト編集中のキー
- `Enter`: 確定する。 `Escape`: 取り消す。入力欄の外をクリックすると確定する。
- Tab で追加した直後の空のノードは、空のまま確定するか `Escape` で取り消すと破棄される。
- 編集中は、上記のノード操作のショートカットは無効になる（入力欄のテキスト操作が優先される）。

### 設計上の判断
- 仕様の初版では `Enter` が「兄弟ノードの追加」と「テキスト編集」の両方に割り当てられていたため、**編集は `F2`（とダブルクリック）、`Enter` は兄弟ノードの追加**に統一した。
- 「元に戻す」の単位は、ノードの追加＋テキスト入力の確定を 1 手とする。矢印キー・クリックによる選択の移動、コピーは履歴に残さない。
- ファイルを開くと、元に戻す履歴は新しくなる（別の文書として扱う）。
- 編集中のテキストが入力欄にある間は保存・書き出し・ファイルを開く操作は無効（先に確定する）。
- **未保存の変更**: 最後に保存した（または開いた）時点のマップと違えば「未保存」とみなし、画面左下に「ファイル名 ● 未保存」と表示する（保存先がなければ「無題」）。保存したときの状態まで「元に戻す」と、未保存ではなくなる。選択の移動やコピーは、変更として扱わない。
- **ウィンドウを閉じるときの確認**: 未保存の変更があるときにウィンドウを閉じる（アプリを終了する）と、同じ確認ダイアログを出す。キャンセルするか、確認のダイアログが失敗したときは、閉じない。
- **ファイルを開くときの確認**: 未保存の変更があるときに `Cmd + O` を押すと、「破棄して続ける / キャンセル」の確認ダイアログを出す。キャンセルすると、ファイルを開かず、編集中のマップも変えない。

## 4. 開発プロセス・品質保証
- **開発手法**: TDD (Test-Driven Development)
- **カバレッジ目標**: ユニットテストカバレッジ 100% を目指す。最低要件として **95%** は必須。
- **例外規定**: UIレンダリング（特にSVG出力や曲線のピクセル調整など）やネイティブAPI（Rust側）の結合部分などで、テストの実装コストが非常に高い場合は、AI(Claude)から人間に「費用対効果の判断」を仰ぐこと。
- **構成管理**: GitHub (Public) にて管理。

## 5. 描画の仕様
- **配置**: 中心ノードを原点に置く放射状レイアウト。最初のメインブランチは右向きの中心に置き、以降は時計回りに並べる。各ブランチは、含まれる葉（折りたたまれたノードは 1 枚）の数に比例した扇形を使う。
- **ブランチ**: 親から子へ向かう三次ベジェ曲線（S 字）。線幅は深さが増えるほど細くなる。
- **色**: メインブランチごとにパレット（8 色、白背景でのコントラスト比 3:1 以上）から割り当て、子孫は同じ色を引き継ぐ。色はメインブランチを作成したときに決めて、ノードに保存する（`branchColor`）。パレットのうち、最も使われていない色（同数ならパレット順で先頭）を割り当てるので、メインブランチを削除しても、他のブランチの色は変わらず、空いた色が次に使われる。
- **テキスト**: ブランチ上のテキストは、枝の中点に白い縁取り付きで置く。折りたたまれたノードは、ラベルの末尾に `…` を付ける。
- **スタイル**: ノードごとに、太字・斜体・色・フォント・文字サイズを設定できる。色は、そのノードの文字と、親から伸びる枝だけに効く（子孫には引き継がれない）。既定は標準の太さ。

## 6. ファイル形式
### JSON（`.json`、フォーマットバージョン 1）
```json
{
  "version": 1,
  "rootId": "…",
  "nodes": {
    "<id>": {
      "id": "<id>",
      "kind": "central | branch",
      "text": "…",
      "parentId": "<id> | null",
      "childIds": ["<id>", "…"],
      "position": { "x": 0, "y": 0 },
      "collapsed": true,
      "branchColor": "#RRGGBB",
      "style": { "bold": true, "italic": true, "color": "#RRGGBB", "fontFamily": "…", "fontSize": 20 }
    }
  }
}
```
- `collapsed`、`branchColor`（中心ノードの直下のノードだけが持つ）、`style` は省略可能。`style` の各項目も省略可能。`branchColor` のない従来のファイルは、ブランチの並び順から色を決める。
- 読み込み時は、次を検証し、不正なファイルは日本語のエラーメッセージで拒否する（編集中のマップは変更しない）。
  - JSON として正しいこと、`version` が対応済みであること
  - 各ノードの形式（`style` は、有効な項目だけを持つこと。未知の項目は拒否）
  - ルートが 1 つで親を持たないこと、`childIds` と `parentId` が互いに整合していること、ルートから到達できないノードがないこと
- 読み込めるファイルの大きさは、最大 50 MB。
- 保存は、同じフォルダの一時ファイルに書いてから置き換える（保存の途中で失敗しても、元のファイルを壊さない）。

### SVG（`.svg`）
画面と同じ描画規則で、表示されているノード（折りたたまれた子孫を除く）を、白背景の SVG として書き出す。保存先は、JSON の保存先とは独立している。

## 7. 実装状況
### 実装済み
- 中心ノード、子・兄弟の追加、テキスト編集、削除、ノード間の移動
- 放射状レイアウト、曲線のブランチ、メインブランチごとの色
- 折りたたみ・展開、コピー/ペースト/カット、元に戻す/やり直す
- スタイル（太字・斜体・色・フォント・文字サイズ）とスタイルパネル
- システムのクリップボードとの連携（IdeaTree のサブツリーと、普通のテキスト）
- JSON の保存・読み込み、SVG の書き出し、未保存の変更の表示と、ファイルを開くとき・ウィンドウを閉じるときの確認
- クリックによる選択、ダブルクリックによる編集
- ノードの移動・並べ替え（`Option + 矢印キー`、マウスのドラッグによるつなぎ替え）

### 未実装・今後の課題
- 色は 8 色のパレットのみで、任意の色（`#RRGGBB`）の入力はできない。
- セントラルイメージとしての画像や、ノードへの画像・アイコンの追加。
- 画像や、インデントによる階層を持つテキストの貼り付け。
- ドラッグでの兄弟の順序の指定（今は、ノードの子へのつなぎ替えのみ。順序はキーボードで入れ替える）、ズーム・パン。
- ノードのクリック判定の拡大（現状は、文字と中心の楕円の上だけ）。
